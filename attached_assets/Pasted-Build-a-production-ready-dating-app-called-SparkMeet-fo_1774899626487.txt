Build a production-ready dating app called "SparkMeet" for iOS.

CONCEPT:
People connect through shared activities and local events — 
no endless swiping. Users join events (cooking class, hiking, 
game night, yoga, etc.), meet 4-8 other singles there, and 
can anonymously like each other afterwards. Mutual likes 
become matches with a private chat.

TECH STACK:
- React Native + Expo (managed workflow)
- Supabase for backend (auth, database, storage, realtime)
- RevenueCat for in-app subscriptions (StoreKit 2)
- Expo Notifications for push notifications
- React Navigation (bottom tabs + stack)
- NativeWind for styling (Tailwind in React Native)

DATABASE SCHEMA (Supabase):
Table: profiles
- id (uuid, FK to auth.users)
- display_name (text)
- age (int)
- bio (text, max 300 chars)
- profile_images (text[], max 6 URLs)
- interests (text[])
- city (text)
- gender (text)
- looking_for (text)
- is_pro (boolean, default false)
- pro_expires_at (timestamptz)
- notification_token (text)
- events_joined (text[])
- created_at (timestamptz)
- last_active (timestamptz)

Table: events
- id (uuid)
- title (text)
- description (text)
- category (text) -- Kochen, Wandern, Sport, Kultur, Spieleabend, Café, Konzert, Yoga
- host_id (uuid, FK profiles)
- host_name (text)
- image_url (text)
- location_name (text)
- address (text)
- latitude (float)
- longitude (float)
- event_date (timestamptz)
- duration_minutes (int)
- max_participants (int, 4-12)
- current_participants (text[])
- price (float, default 0)
- is_premium_only (boolean, default false)
- status (text) -- upcoming, active, completed, cancelled
- tags (text[])
- created_at (timestamptz)

Table: matches
- id (uuid)
- user_id_1 (uuid)
- user_id_2 (uuid)
- event_id (uuid)
- status (text) -- pending, matched, declined
- initiated_by (uuid)
- last_message (text)
- last_message_at (timestamptz)
- created_at (timestamptz)

Table: messages
- id (uuid)
- match_id (uuid, FK matches)
- sender_id (uuid)
- text (text)
- is_read (boolean, default false)
- created_at (timestamptz)

Table: event_likes
- id (uuid)
- event_id (uuid)
- from_user_id (uuid)
- to_user_id (uuid)
- created_at (timestamptz)

ROW LEVEL SECURITY (Supabase RLS):
- Users can only read/write their own profile
- Events: everyone can read, only host can update/delete
- Matches: only the two matched users can read
- Messages: only match participants can read/write
